# 客服与研发协同升级规范（模拟）

> 本文件为虚构演示数据，人物、时限和流程均为测试内容，不对应任何企业的真实制度。

## 1. 事件分级

### P0 重大安全事件

涉及人员伤亡、失联、重大交通事故、目的地重大灾害或大规模旅客滞留。发现后立即通过电话和值班群同时通知客服负责人、研发负责人、法务和公关。

### P1 大规模订单或系统异常

影响超过 50 笔订单、核心预订流程不可用、支付状态与订单状态不一致，或短时间内出现集中投诉。值班负责人在 15 分钟内响应。

### P2 一般知识库或客诉问题

单笔订单争议、答案引用错误、文档版本冲突或客服无法判断的退改问题。工作时间内 2 小时内响应。

## 2. 知识库答案纠错流程

1. 客服提交问题、会话编号、引用文档和错误说明。
2. 知识库管理员确认引用版本是否为当前版本。
3. 文档负责人修订制度，并生成新版本。
4. 管理员重新索引并执行回滚验证。
5. 抽样提问确认新版本优先命中。
6. 将验证结果关联到原反馈记录。

## 3. 权限要求

- 普通客服只能查看客服政策空间和本人有权限的订单信息。
- 研发人员只能查看研发制度和技术手册，不得访问用户个人信息空间。
- 管理员可以管理成员和文档，但高风险操作必须保留审计日志。
- 任何角色都不得通过对话接口绕过空间权限读取文档。

## 4. 升级记录

升级工单至少记录：事件等级、发现时间、影响范围、当前状态、负责人、下一次更新时间、关联订单、关联会话和复盘结论。

事件解决后 5 个工作日内完成复盘，区分直接原因、系统性原因和长期改进项。涉及个人信息的事件还必须通知数据保护负责人。
