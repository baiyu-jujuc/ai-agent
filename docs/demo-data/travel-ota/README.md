# 旅游 OTA 演示数据

这些文档用于演示多知识空间、文档版本、引用溯源、权限和置信度。所有制度和数字均为虚构测试数据，不对应途牛或任何企业的真实政策。

## 文件用途

- `regulatory-baseline.md`：根据政府公开法规整理的摘要，保留原文链接。
- `refund-change-policy-v1/refund-change-policy.md`：退改制度初始版本。
- `refund-change-policy-v2/refund-change-policy.md`：退改制度更新版本，用于版本回滚。
- `customer-service-escalation.md`：客服与研发协同的升级处置制度。

两个退改文档必须使用相同的文件名 `refund-change-policy.md` 上传到同一知识空间，系统才会把它们识别为同一文档的两个版本。

## 推荐提问

1. 申请退改时提前多少小时可以免平台服务费？
2. 台风导致航班取消，客服应该先做哪些处理？
3. 不可抗力导致行程无法继续时，退款依据是什么？
4. P1 客诉多长时间内必须升级到值班负责人？
5. 用户要求删除个人数据时，知识库团队需要做什么？

## 版本回滚验证

当前版本 v2 的免平台服务费申请时限是 72 小时。回滚到 v1 后，同一问题应回到 48 小时。这个差异可以直观证明系统使用的是当前有效版本，而不是历史分块拼凑答案。

## 使用边界

这些材料仅用于个人作品集和本地演示。不要把第三方企业公开页面整页复制进仓库，不要声称拥有第三方内部资料，也不要把模拟制度描述成真实企业制度。
