# 星云科技生产发布与回滚手册

版本：1.0

状态：已生效

适用范围：核心业务服务

## 1. 发布窗口

常规生产发布仅允许在周二、周四 20:00 至 23:00 执行。每周五 16:00 后进入变更冻结期，周末和法定节假日前最后一个工作日不安排非紧急发布。

紧急修复需要由研发负责人和运维负责人共同批准，并至少提前 30 分钟通知值班人员。

## 2. 发布前检查

发布申请必须包含变更内容、影响范围、回滚方案、验证清单和负责人。缺少任一项时，运维有权拒绝发布。

发布前应确认：

1. 自动化测试全部通过。
2. 数据库变更脚本已完成评审。
3. 核心指标和告警处于正常状态。
4. 上一可用版本和配置已保留。

## 3. 发布过程

生产发布采用分批灰度。第一批流量不超过 5%，观察 10 分钟；第二批流量提升至 20%，观察 15 分钟；无异常后再全量发布。

如果错误率连续 3 分钟超过 1%，或 P95 延迟连续 5 分钟超过 2 秒，应立即暂停发布并评估回滚。

## 4. 回滚规则

P0 故障必须在 10 分钟内完成应用回滚或流量切换。回滚完成后，负责人需要在事件群同步当前版本、数据状态和影响范围。

数据库结构变更优先采用向后兼容设计。无法直接回滚的数据变更必须提前准备补偿脚本，不得依赖人工逐条修复。

## 5. 备份策略

生产数据库每天 02:00 执行全量备份，备份文件保留 30 天。每周日 03:00 执行一次恢复演练，演练结果由数据库负责人签字确认。
