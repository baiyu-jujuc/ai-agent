# 2-3 分钟演示视频脚本

这份脚本的目标不是“展示聊天”，而是让面试官在 3 分钟内看到一条完整的企业知识库链路：空间隔离、持久化、文档版本、权限、引用、置信度、多轮问答和反馈。

## 一、录屏前准备

### 1. 启动完整环境

在项目根目录执行：

```powershell
.\scripts\docker-start.ps1 start
wsl -d Debian -- bash -lc 'cd "/mnt/d/AI Agent (test)" && docker compose up -d --build'
```

如果你使用 Docker Desktop，第二条命令可改为：

```powershell
docker compose up -d --build
```

检查四个服务：

```powershell
wsl -d Debian -- bash -lc 'cd "/mnt/d/AI Agent (test)" && docker compose ps'
```

预期看到 `app`、`mysql`、`redis`、`qdrant` 四个容器。App 映射到 `http://localhost:8080`。

### 2. 创建演示账号与文档

```powershell
.\scripts\demo-prepare.ps1
```

脚本使用以下账号，数据会写入 Compose 的 MySQL：

| 角色 | 用户名 | 密码 | 用途 |
| --- | --- | --- | --- |
| 管理员 | `admin` | `123456` | 创建空间、上传文档、回滚、问答 |
| 普通成员 | `reader` | `123456` | 只读成员；验证无权限空间会返回 403 |

> `123456` 仅用于本地录屏和面试展示。部署到公网前必须更换为强密码，并同步修改平台访问 Key。

演示数据：

- `docs/demo-data/employee-handbook.md`
- `docs/demo-data/release-manual-v1/release-manual.md`
- `docs/demo-data/release-manual-v2/release-manual.md`

两个 `release-manual.md` 文件名相同，因此会形成同一个文档的 v1 和 v2。v1 的周五冻结时间是 16:00，v2 改为 18:00，回滚后可以直观看到引用版本切回 v1。

### 3. 先跑自动验收

```powershell
.\scripts\demo-smoke.ps1
```

只有出现“演示链路全部通过”后再开始录屏。该脚本会验证：

1. 最新版本问答命中 v2 引用。
2. 多轮追问保留上下文。
3. 反馈成功写库。
4. 回滚到 v1 后引用版本变为 v1。
5. 普通账号访问管理员空间返回 403。

## 二、录屏设置

1. 浏览器缩放设为 100%，关闭无关标签页、通知和聊天软件。
2. 使用 1920x1080 分辨率，Windows 直接使用 `Win + G` 录屏即可。
3. 平台访问 Key 使用 `dev-key-change-in-production`，在页面右上角设置中保存。
4. 提前登录一次再退出，确保账号和空间数据已经存在。
5. 录屏时不要展示 `.env`、终端中的 API Key、浏览器开发者工具或云服务器登录信息。

## 三、推荐镜头与口播

### 00:00-00:15 工程启动

画面：终端显示 `docker compose ps`，四个服务处于运行状态。

口播：这是基于 Java 21、Spring Boot 和 Spring AI 的企业知识库问答平台。元数据持久化在 MySQL，会话缓存使用 Redis，向量服务使用 Qdrant，应用只暴露一个业务端口。

### 00:15-00:35 登录与知识空间

画面：使用 `admin` 登录，顶部选择“产品研发知识库（演示）”。

口播：系统不是单会话聊天 Demo，而是以知识空间为隔离边界。普通账号只能看到被授权空间，管理员负责成员和文档管理。

### 00:35-01:05 文档上传与版本回滚

画面：打开文档管理，上传员工手册和发布手册。点击发布手册的“版本”，展示 v2 为当前版本，再回滚到 v1。

口播：同名文档重新上传会生成新版本。回滚不会删除历史数据，旧版本分块重新启用，新版本分块停用，向量索引同步切换。

### 01:05-01:35 引用问答与置信度

画面：选择知识空间，提问“生产发布每周五几点进入变更冻结期？”。展示流式或完整回答、`[1]` 引用和置信度。

口播：回答只使用当前空间内有权限访问的文档片段，并返回文档、版本、分块、相似度、置信度和消息编号，便于追溯。

### 01:35-01:55 引用溯源

画面：点击 `[1]`，展开引用原文，停留 2-3 秒。

口播：每条引用都能回到原文片段和版本号，不是只给一个无法验证的模型答案。

### 01:55-02:20 多轮上下文与反馈

画面：继续追问“那 P0 故障的回滚要求是什么？”，然后点击“有用”。

口播：追问会携带最近 20 条会话消息，但上下文按用户、空间和 conversationId 隔离。反馈会记录到对应消息，供后续质量分析。

### 02:20-02:40 权限校验与测试结果

画面：退出管理员，登录 `reader`，尝试访问“管理员专属”空间，显示无权限或 403；切到 GitHub Actions，展示测试全绿。

口播：权限不仅控制页面显示，服务端每个知识库接口都会执行 canRead、canWrite 或 canAdmin 校验，避免前端绕过。

## 四、录完后的检查

- 视频中没有任何真实 API Key、密码、客户信息或未脱敏文档。
- 版本回滚前后都能看到版本号变化。
- 回答中至少出现一个可点击引用。
- 普通账号访问未授权空间确实失败。
- 视频长度控制在 3 分钟以内，导出为 1080p MP4。

可在剪映中自动生成字幕，但需要人工检查“Qdrant、SSE、canRead、conversationId”等工程术语。

## 五、录制失败时的排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 上传后一直无文档 | 前端或接口鉴权失败 | 确认平台 Key、JWT 均已配置，再执行 `demo-smoke.ps1` |
| 回答提示模型失败 | `DEEPSEEK_API_KEY` 无效或模型名不可用 | 先运行普通对话接口，再检查 `.env` |
| 版本页只有 v1 | v2 没有以同名文件上传 | 使用 `demo-prepare.ps1` 自动准备 |
| 引用没有原文 | chunk 或消息归属校验失败 | 查看 app 日志，确认没有跨空间查询 |
| 重启后账号消失 | 应用仍在使用 H2 | 确认 Compose 注入了 `SPRING_DATASOURCE_URL` |
