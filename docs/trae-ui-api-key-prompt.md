# Trae 执行提示词：页面级 API Key 与浅色 UI

> 工作目录：`D:\AI Agent (test)`
> 基线：以你交付给 Trae 的干净分支/工作区为准；若工作区里已有其他未提交修复，请先确认是否包含在交付范围内，避免 Trae 误改无关模块。
> 本文档只描述“页面模型 Key 配置”和“浅色 DeepSeek 风格 UI”两项任务，不要顺手做无关的大范围重构。

## 1. 任务背景与目标

项目是 Java 21 + Spring Boot 3.4 + Spring AI 的企业知识库问答平台。当前页面为单文件 [index.html](../src/main/resources/static/index.html)，服务端通过环境变量 `DEEPSEEK_API_KEY` 调用大模型，页面里的 Key 输入框实际只代表平台接口鉴权 `AGENT_API_KEY`，不代表模型服务 Key。

用户希望达到两个目标：

1. 让别人拉取并运行本项目时，不必先理解并修改服务端 `.env`，也能在页面里配置模型 API Key，至少让“本地/私有部署体验”完整。
2. 页面改成浅色、简洁、接近 DeepSeek 对话页的风格，全部面向中文用户，所有入口、选项、提示优先中文。

## 2. 隐私基线：先确认现状

完成任何 UI 改动前，先核对并保持以下安全基线：

- `DEEPSEEK_API_KEY` 只能存在于服务端环境变量 / 服务端配置中。
- 页面、接口响应、日志、错误页都不能回显 `DEEPSEEK_API_KEY`。
- 前端只保存平台访问 Key（`AGENT_API_KEY`），并仅在请求头 `X-API-Key` 中发送。
- 不要把任何真实 Key 提交到仓库；继续忽略 `.env`。
- 不要把 Key 放进 URL、`localStorage` 的明文调试字段、浏览器 console 或 toast。
- 检查仓库内是否有 `sk-`、真实 Key、`.env` 文件被跟踪；若有，先移除并改写历史前不要推送。

## 3. 页面级模型 Key：推荐设计

### 3.1 默认模式：服务端环境变量（必须保留）

默认仍从服务端环境变量读取模型 Key。README 中保留“自部署用户需配置 `.env`”的说明。

页面应明确区分两个 Key：

- “服务器地址”
- “平台访问 Key”：发送到后端 `X-API-Key`，是服务端 API Key。
- “模型 API Key（可选，仅私有部署开启）”：仅在服务端允许该模式时显示并生效。

### 3.2 可选模式：前端携带模型 Key

该模式默认关闭，通过配置开启，例如：

```properties
agent.security.allow-client-model-key=false
```

开启后，页面可以提供一个“模型 API Key”输入框，并满足：

- 前端只在用户点击“使用自定义模型 Key”后读取该值。
- 前端默认不持久化；若需要记住，必须存入 localStorage 并在页面明示“仅保存在当前浏览器”。
- 每次请求通过独立的请求头（如 `X-Model-API-Key`）传给后端，由后端临时用于对应 LLM 请求。
- 后端必须在请求完成后清理临时 Key，不写入日志、缓存、数据库或配置。
- 后端不把前端提供的 Key 用于网络搜索、HTTP 工具或其他外部接口。
- 若请求头缺失，则回退到服务端 `DEEPSEEK_API_KEY`。
- 页面上的模型 Key 输入框使用密码样式，提供“显示/隐藏”和“清除”。
- 后端接口返回中不得包含该 Key。

### 3.3 不建议的实现

不要直接把模型 Key 拼进普通聊天请求体或 URL，不要让它进入浏览器历史，不要在多人共用服务器上默认开放“任意用户输入模型 Key”的能力。

## 4. UI 任务

### 4.1 整体风格

参考 DeepSeek 官方对话页的“浅色、留白、居中对话、干净状态条”的视觉感受，但不要复制其商标或素材。

要求：

- 主背景浅色（接近 `#ffffff` / `#f6f7f9`），不使用深色主题。
- 主对话区窄于全屏并居中，最大宽度建议 `720-860px`。
- 气泡和输入区使用白底或极浅灰底，辅助边框使用浅灰。
- 强调色使用克制的蓝/青蓝，避免大面积紫色渐变。
- 头像、图标、按钮使用简洁线型图标；按钮必须能通过 title/tooltip 表达含义。
- 页面所有可见文案默认中文，例如“新对话”“清空”“发送”“使用工具”“流式回复”“模型”“Agent”“知识空间”“服务器设置”等。
- 不出现“功能介绍大段文字”，界面以可操作为主。
- 消息文本必须自适应换行，任何长内容都不能溢出或遮挡。

可参考的浅色 UI 项目（只参考布局和配色，不直接搬代码或依赖，除非能说明收益）：

- [NextChat](https://github.com/ChatGPTNextWeb/NextChat)
- [Open WebUI](https://github.com/open-webui/open-webui)
- [LobeChat](https://github.com/lobehub/lobe-chat)
- [Chatbot UI](https://github.com/mckaywrigley/chatbot-ui)

### 4.2 页面布局建议

建议采用“顶部工具条 + 居中对话 + 轻量侧栏/抽屉”：

- 顶部：品牌名/助手名、模型选择、Agent 选择、工具开关、流式开关、设置按钮。
- 中部：对话消息流；助手消息显示引用或执行轨迹时使用清晰的分区，不允许嵌入重复卡片。
- 底部：多行输入框和“发送”按钮，快捷键提示可用中文短文本，如“Enter 发送 / Shift+Enter 换行”。
- 设置弹窗：必须可被打开，包含服务器地址、平台访问 Key、可选模型 Key、保存/清除。
- 窄屏：顶部选项收敛为抽屉或下拉，不能出现横向溢出；设置必须可用。

### 4.3 中文展示规则

- Agent 列表显示中文名称，同时可附英文代码小字，如“协调 Agent (coordinator)”。
- 模型下拉显示中文说明，但提交给 API 的值保持模型 ID。
- 开关文字用“启用工具调用”“启用流式输出”。
- 按钮不要用只放一个英文单词的方式表达。
- 错误消息全部中文。

### 4.4 保留现有交互

无论是否重写页面，以下功能必须继续可用：

- 普通对话、指定 Agent 对话、启用工具调用。
- SSE 流式解析，结束事件 `[DONE]`。
- 工具列表加载和单工具测试。
- 清空历史、新对话、多 Agent 编排演示和轨迹展示。
- 服务器地址、平台 Key 的本地保存。
- 存储状态展示。
- 无 Key GET 接口可访问，POST 接口正确携带 `X-API-Key`。

## 5. 安全与隐私验收

- 页面模型 Key 不进入任何普通日志。
- 所有 Key 输入框为密码类型；表单提交后不打印到 console。
- 浏览器请求头中只包含必要 Key，Key 不进入 URL。
- 没有真实 `.env` 或真实 Key 被跟踪。
- `git status` 中不出现 `.env`。
- 页面改动不能使旧接口签名失效；若需要新增 header，请保持旧调用兼容。

## 6. 测试与验收

如果只改前端静态文件：

```bash
mvn test --no-transfer-progress
```

如果同时改后端以支持自定义模型 Key：

```bash
mvn clean verify --no-transfer-progress
```

手工检查清单：

1. 新用户拉取后不配置环境变量，也能在页面看到“需要服务端配置”的明确状态。
2. 开启自定义模型 Key 后，可向服务端发起一次成功请求。
3. 不开启时，后端仍使用 `DEEPSEEK_API_KEY`。
4. 页面在 1440px、1024px、390px 宽度下无文字遮挡、无横向滚动。
5. 所有入口、按钮、选项均以中文为主。
6. 页面整体为浅色，无深色背景块。
